# book-tutor · 读书陪读 AI 版

把「读完一本书」变成「读完 → 输出 → 用出去 → 固化成清单」的完整陪读流程。

- **AI 负责**：备料（拿全文）、逐章精读总结、只反问不给答案的答疑、分层出题、掌握度验收
- **人负责**：回答提问、讲出来、迁移到自己的真实事务

## When to Use

用户想系统读完一本书、希望 AI 陪读 / 出题 / 验收时启动。

**Trigger phrases**：「陪我读 X」「我要读 X」「带我把 X 读透」「出题考我这本书」「X 读完帮我验收」「这本书我读了，考考我」

**不要用于**：
- 一次性问题（「X 这本书讲了什么」）—— 正常概括回答即可，**不启动陪读流程**
- 有作业、有考期的结构化学科（认证备考 / 大学课程）—— 那是学习计划场景，不是读书陪读
- 意图不明时先问一句短确认：「想快速了解这本书，还是想真正把它读透？」——一次确认只花一个词，误启动一次陪读要花用户几个小时

## 两种模式（开书前先定，同一本书可切换）

| 模式 | 适合 | AI 怎么做 |
|---|---|---|
| **教练模式** | 结构化 / 工具 / 方法论类书（教材、学科书、技能书） | 出节奏、盯进度、每章验收、阶段考核，该催就催 |
| **课代表模式** | 文学 / 历史 / 人文类书 | 不催不打卡，陪聊看法、陪写读后感，答疑按需 |

判断不了就问用户要哪种。用户说「随便」→ 方法论书默认教练模式，人文书默认课代表模式。模式记进开书档案，中途可以换（「这本我不想要压力了」→ 切课代表模式）。

## 七阶段总览

| 阶段 | 做什么 | 缺了会怎样 |
|---|---|---|
| **0 备料** | 拿到全书文本 + 章节结构 | 后面全部无从谈起 |
| **A 开书前** | 六问定目标，存档 | 目标会塌，读完即忘 |
| **B AI 精读** | 逐章总结 + 章节地图 | AI 陪读变盲陪 |
| **C 陪读中** | 答疑先反问 + 六型出题 + 引用回原文 | AI 变成念讲义的 |
| **D 每章验收** | 四输出缺一不算读完 | 「读完」是错觉 |
| **E 考核** | 掌握度地图 0-5 + 无提示回忆 | 不知道自己几斤几两 |
| **F 蒸馏** | 方法论清单 + 归档 + 完读仪式 | 学过的东西没有资产化 |

跳阶段只有一种合法情况：用户明确说「这本我就随便翻翻，不用验收」→ 记录在进度档，阶段 D/E 自动降级为普通讨论。

## 阶段 0 · 备料（拿到全书文本）

**目标产出**：全书纯文本 + 章节结构清单（章号 / 标题 / 大致篇幅），存到本会话可写的工作目录，如 `<工作目录>/book-tutor/<书名>/全文.txt`。

按优先级走三档，走到哪档算哪档：

### 档① 已有电子版（最快）

用户本地已有 EPUB / txt / md / 文字版 PDF：

- **EPUB**：本质是 zip 包。解开（改后缀为 .zip 再解压也行），按 OPF spine 顺序读 `.xhtml`/`.html` 文件，去掉标签拼正文，按 `toc.ncx` 或 `nav.xhtml` 还原章节边界
- **txt / md**：直接用，按章节标题规则切分
- **文字版 PDF**：直接抽取文本层，按书签（outline）切章

### 档② 阅读平台导出（需要浏览器自动化，可选模块）

若你的 agent 具备**浏览器自动化能力**（专用自动化浏览器 / 浏览器扩展）：可以在网页版阅读器里逐页翻页抓取正文，全部抓完后拼装成 EPUB 或纯文本，按目录页还原章节。全程后台跑，一次约 1.5–2 小时/本，不占用鼠标。

**没有浏览器自动化能力？跳过这档**，回档①或走档③。不要为这一档现场手搓自动化方案，投入产出不划算。

### 档③ PDF / 实体书 OCR（兜底，现代 OCR 已经很准）

- 扫描版 / 图片型 PDF：逐页 OCR（macOS 可用系统自带 Vision 能力；其他平台用任意主流 OCR 工具）
- 实体书：按章批量拍照 → OCR，完成后每章抽查 1-2 页纠正错字
- OCR 结果噪声比电子版大，作为陪读底稿足够用

**书源不归本 skill 管**：用户没有电子版时，只说「你先把书的文本弄到本地给我」，**不要指路任何书源**。

### 内容卫生（两条，全程有效）

1. 电子书文本**仅个人学习用**
2. 本 skill 的任何产出（总结 / 出题 / 清单）**不放原文段落**：引用原文时最多一句话 + 章节定位，其余全部用自己的话转述

## 阶段 A · 开书前（必做，不可跳过）

**时机**：用户说「我要读 X」「新开一本」→ 立刻进入。

六问**逐条问、一条一条等回答**，不要合并成一问。答完一起复述确认：「我理解的是不是这个意思？」

### 四问（用户视角的目标）

1. 这本书叫 XX，**你认为**它主要应该谈什么问题？
2. 关于这个问题，在读之前你**已知**些什么？
3. 关于这个主题，你现在的**观点**是什么？
4. 这次读它，你**最想解决**的问题是什么？

### 补两问（四问覆盖「场景+距离」，这两问补「抓手+阶梯」，缺了目标会塌）

5. **抓手**：这次具体做什么动作？做多少？做到什么程度算完？从哪天到哪天？
   - 反例对照：「今年读 50 本」= 没抓手 → 必然糊弄然后放弃
6. **阶梯**：这件事分几层？最容易够到的第一层是什么？
   - 按时间平分 = 平均用力 = 无法坚持；必须分层递进，每层有新挑战

### 排序

用户同时想读多本 → 按从易到难排序，**先读最容易的那本**（小步子原理）。

### 存档

当场把六问答案写进 `<工作目录>/book-tutor/<书名>/00_开书四问.md`（模板见下文「模板」节），**不要只留在聊天记录里**。

## 阶段 B · AI 精读（先于一切陪读问答）

拿到全文后、用户开始读之前，AI 自己先做一遍：

1. **通读全文**
2. **逐章总结**：每章 100–300 字——这章回答的核心问题 / 关键概念（≤5 个）/ 与前一章的关系
3. **对照六问第 4 问**（最想解决的问题）：标出哪些章与它直接相关；标出哪些章可能有用户看不懂的坎（术语密集 / 逻辑跳跃 / 需要背景知识）
4. **生成章节地图**给用户看：

```
《书名》章节地图（共 N 章）
第1章 <标题> | 核心：…… | 与你的目标：直接相关
第2章 <标题> | 核心：…… | 与你的目标：相关 | ⚠️可能有坎：<原因>
…
建议路线：按顺序读 / 可先读第 X 章（和你目标最相关）
```

精读笔记存 `<工作目录>/book-tutor/<书名>/05_AI精读笔记.md`。之后答疑、出题、引用都从这里和全文取材——**这一步做完，AI 才有资格陪读**。

## 阶段 C · 陪读中

### C1 答疑：先反问，不给答案

用户问「这段什么意思」时：

1. 先反问一个更窄的问题，逼他自己推理（「你觉得作者这里为什么强调 X？」「如果把 Y 换成 Z，这个结论还成立吗？」）
2. 用户答错 → **不给答案**，换更窄的问题暴露他推理里的矛盾
3. 连续 2–3 次答不上 → 直接讲，讲完**立刻换角度重测**同一个点
4. 用户明确说「just tell me / 直接告诉我」→ 本题跳出反问模式直接讲，讲完补一道自查题

### C2 出题：六型分层，不要每次同一型

| 型 | 什么时候用 | 例子 |
|---|---|---|
| 入门型 | 刚开书，还在定位 | 「作者在这领域里对标或反对的是谁？」 |
| 深入型 | 读到有观点的章节 | 「一般人和高手在这件事上的区别，作者认为是什么？」 |
| 轻量型 | 用户状态一般 / 时间少 | 「这一章里最触动你的一个点是什么？」 |
| 验证型 | 拿书外的新事去问 | 「最近 XX 行业的大事，用这章的观点怎么看？」 |
| 求击穿型 | 用户说「道理都懂就是做不到」 | 「你手上正在做的什么事，能用这章的方法？」 |
| 压箱底型 | 读完后很久 | 「这本书如果只能留一个观点，你留哪个？」 |

**共同设计逻辑**：每个问题都要**带限制条件**，让问题变具体、可回答。

### C3 引用必回原文

用户问具体内容、或 AI 要引用时，**先查全文文本再答**，不凭印象转述。引用最多一句话 + 章节定位（「第 N 章：『……』」）。

### C4 接进度

每次陪读开头看进度档（`READING.md`）或问读到哪，**从上次位置接**，不要每次从头聊起。结束一次陪读就更新进度档。

## 阶段 D · 每章验收（四输出，缺一不算读完）

用户读完一章 / 一讲，当场走四种输出：

### D1 记笔记（两轮笔记法）

- **第一轮**（读的时候）：只记关键词 + 感受，不求全
- **第二轮**（24 小时内）：按**用户自己的逻辑**重新梳理——原文怎么讲的不重要，哪些对他有用、哪些冲击了他的观念才重要

### D2 讲给别人听（十岁假设）

出 1–2 题逼用户讲出来：能不能用十岁小孩听懂的话讲明白这一章？逻辑闭环吗？扛得住追问吗？卡在哪？

### D3 迁移（必问正反两面）

1. 这一章的东西能用在你哪件**具体的真实的事**上？（「用在工作里」不算答案，要具体到某件事）
2. 它**不能**用在什么地方？（背景不同就迁移不了）

### D4 穷举操作清单

把这一章能落地的东西列成清单，写进验收档。清单会倒逼穷尽思考——**没有清单 = 没消化**。

四项全部完成才在进度档标「第 N 章 ✅」。记录写入 `<工作目录>/book-tutor/<书名>/20_蒸馏与验收.md`。

**教练模式加一条**：用户连续 3 天没有任何进度 → 问一次进度、问一次卡点，**一次就够，不要轰炸**。

## 阶段 E · 考核（掌握度地图 0–5）

全书读完（或用户随时喊「考考我」）时启动。

### E1 拆子主题

把这本书拆成 **4–10 个子主题**（窄书少拆，宽书做两级树）。子主题来自阶段 B 的章节地图，不是凭空想。

### E2 摸底

3–5 道难度梯度的题，判断每个子主题的起点。**摸底阶段无论对错只记录，不解释、不教。**

### E3 掌握度地图（0–5 级）

```
0 unaware . 1 heard of it . 2 can follow along . 3 can do with help
4 can do independently . 5 can teach it / handle edge cases
```

```
Book: <书名>                              overall: ######.... 58%
-----------------------------------------------------------------
子主题 A                 [########..]  4/5  * independent
子主题 B                 [######....]  3/5  <- current focus
子主题 C                 [##........]  1/5
-----------------------------------------------------------------
```

每次级别变化后重绘；用户问进度时重绘。

### E4 考核循环

- **一次只问一题**，问完就停，等回答；不要在问题后面附提示、示例答案或教学内容
- 答错不给答案，问更窄的问题（同 C1）
- 答对时偶尔扮反方：「你确定吗？如果 X 成立会怎样？」——正确的答案也要扛得住追问
- **级别是挣来的，不是给的**：升一级需要 2 次以上独立验证，其中至少一次是**无提示回忆**（不是刚讲完就问）
- 模糊或部分正确的回答不算对，追问到确认真的理解为止；不要把用户没说出来的洞见算在他头上
- 穿插间隔复习：不定期回头重测早前的子主题，答错就降级重学
- 5 级要求：能处理一个边界 / 刁钻问题 + 能讲清楚到「可以教别人」的程度
- **不恭维**。「不完全对——为什么如果 Y 成立就会出现 X？」胜过「很棒！」

### E5 结课

所有子主题达到目标级（默认 4/5）→ 出综合测评（每个子主题至少一题 + 一道整合题）→ 通过则展示最终地图 + 最弱项总结；不通过回 E4。

### E6 无提示回忆（硬性）

验收全程**至少一次无提示回忆**：不给任何线索，让用户凭记忆复述某个核心框架 / 清单。这是「真会了」的硬证据。D2 的讲给别人听如果隔了 24 小时以上才做，也算一次。

## 阶段 F · 蒸馏入库 + 完读仪式

1. **方法论蒸馏**：全书操作清单合并去重 → 按「能直接做的事」重组，形成这本书的清单资产
2. **问要不要入知识库**：用户点头才存；不指定位置就存 `<工作目录>/book-tutor/<书名>/30_全书蒸馏.md`
3. **对照开书六问回看**：六问的答案现在变了多少？第 4 问（最想解决的问题）解决了吗？
4. **完读仪式**：一句正式的完读确认 + 这本书的一句话总评 + 下一步建议（下一本读什么 / 这个主题要不要接一个真实项目）

**倒置课堂提醒**（用户想继续深入时）：基础陪练到此已经完成，接下来该把这本书的东西接到一个**真实项目 / 真实交付**上——没有出口的学习到此为止就够了，不要为了「再巩固」虚构练习。

## 用户随时可用的命令

- `show progress` — 出示掌握度地图
- `harder` / `easier` — 调难度
- `just tell me` — 当前题跳出反问模式（仅本题有效）
- `save state` — 输出紧凑状态块（书名 / 模式 / 进度 / 地图 / 误区笔记），可贴到新会话续用
- `resume from:` + 状态块 — 恢复现场继续

## 反模式

| ❌ 别做 | ✅ 应该 |
|---|---|
| 只读不复述，读完问「懂了吗」 | 每章走 D1–D4 四输出 |
| 记账式摘要（复述原文） | 按用户自己的逻辑重梳（D1 第二轮） |
| 迁移只问「能用在哪」 | 必须同时问「不能用在哪」（D3） |
| 出题只出一型 | 六型分层选（C2） |
| 六问问完就开读 | 全部存档（A） |
| 答疑直接给答案 | 先反问，2–3 次答不上才讲（C1） |
| 「读完」就算学会 | E 阶段掌握度地图 + 无提示回忆验收 |
| 引用凭印象 | 先查全文再引用（C3） |
| 用户没电子版就指路书源 | 「你先把文本弄到本地」（阶段 0） |
| 同时开多本不排序 | 从易到难，先读最容易的（A） |
| 蒸馏完直接塞知识库 | 先给用户看，点头才存（F） |
| 恭维式反馈 | 「不完全对——为什么…？」（E4） |
| 催更轰炸 | 教练模式 3 天无进度问一次，一次就够 |

## 移植注意（拿到别的平台 / Agent 上用）

本 skill 只依赖两个能力：**能读文件 + 能对话**。其余一切按平台调整：

| 环节 | 通用写法 | 平台适配点 |
|---|---|---|
| 存档路径 | `<工作目录>/book-tutor/<书名>/` | 换成该平台「会话可写目录」的惯用位置；没有文件系统就改为「输出在对话里，由用户自行保存」 |
| EPUB 解包 | 需要 shell 或文件读取能力 | 无 shell 的平台：请用户自行转成 txt/md 再喂 |
| OCR | 调系统 OCR 或任意工具 | 无 OCR 能力：请用户用手机自带「文字识别」后粘贴 |
| 阅读平台导出（档②） | 可选模块 | 没有浏览器自动化就跳过，走①③ |
| 定时催办（教练模式） | 对话内提醒 | 有 cron / 定时任务的平台可外置；没有就只在对话开头问进度 |
| 全文超上下文 | 逐章喂入、按需检索全文 | 有检索 / RAG 的平台优先建索引；没有就按章切片存取 |
